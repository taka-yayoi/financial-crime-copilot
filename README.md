# Financial Crime Copilot

**An end-to-end Databricks data journey that cuts a bank's AML alert-triage cost by an estimated $2.1M/year while shortening SAR filing time and keeping every decision auditable.**

> Industry: **Financial Services — AML / Financial Crime**. Author: Takaaki Yayoi.
> All data is **synthetic**, generated by the code in this repo. No real customer data is used.
> Business deck: [`deck/financial-crime-copilot.pdf`](deck/financial-crime-copilot.pdf) ([HTML](deck/financial-crime-copilot.html)).

---

## 1. The business problem (start here)

A mid-size commercial bank's **Financial Crime Unit** runs a legacy rules-based
transaction-monitoring (TM) system. It raises a flood of alerts with a
**false-positive rate above 95%** (95.1% in this build's data). Analysts triage every alert
by hand, and each **Suspicious Activity Report (SAR)** takes ~2 hours to write. The result:

- A growing alert backlog and **regulatory SLA risk**.
- **Analyst labor** spent mostly on false positives.
- Inconsistent SAR quality across analysts.

**Who feels this:** the Head of Financial Crime / Chief Compliance Officer (funds the fix)
and the data/security architect (has to operate it under audit).

## 2. What we built and the value it creates

The **Financial Crime Copilot** keeps the existing rules (regulators trust them) and adds an
intelligence + operations layer on top:

- **ML alert prioritization** ranks every alert by the probability it is genuinely suspicious,
  with **per-alert SHAP reasons** for auditability. Analysts work the queue top-down.
- **GenAI SAR drafting** writes a regulator-style narrative for every high-priority case
  (human-in-the-loop — an analyst reviews, edits and files; nothing is auto-filed).
- **Lakebase** serves the live case queue to the app and records analyst dispositions
  transactionally.
- **Genie Room** lets investigators and managers ask questions in natural language.
- A **Databricks App** is the analyst case cockpit (queue, case detail, SAR editor, KPIs, Genie).

### Measured on this build (synthetic data, held-out test set)

| Result | Value | Evidence |
|---|---|---|
| Legacy false-positive rate | 95.1% (2,298 of 2,417 alerts) | [runs/01](runs/01_data_generation.txt) |
| Model quality | ROC-AUC 0.985, PR-AUC 0.894 | [runs/04](runs/04_ml_alert_scoring.txt) |
| Suspicious cases caught by reviewing only the **top 20%** of the ranked queue | **96.7%** (29 of 30) | [runs/04](runs/04_ml_alert_scoring.txt) |
| High-priority cases with a GenAI SAR draft ready | 121 of 121 | [runs/05](runs/05_genai_sar.txt) |

### Estimated annual value (assumptions stated, not asserted)

| Lever | Assumption | Annual impact |
|---|---|---|
| Alert triage | 100k alerts/yr × 30 min = 50k analyst hours. We assume **40%** of that effort is removed — conservative against the measured result above, where 80% of alerts sit below the review line that still catches ~97% of suspicious cases | 20k hrs × $75 = **$1.5M** |
| SAR drafting | 5k SARs/yr; GenAI draft cuts writing from ~2 hrs to ~20 min of review | 8.3k hrs × $75 = **$0.6M** |
| **Total** | Loaded analyst cost $75/hour | **≈ $2.1M / yr** |
| Regulatory risk | Higher SLA adherence, consistent SAR structure, per-alert explanations | Fine avoidance (not counted) |

**Buyer KPIs moved:** false-positive workload, alert→SAR cycle time, alerts per analyst per day,
SAR quality consistency, regulatory SLA adherence, cost per alert.

## 3. The integrated data journey (one flow, not siloed layers)

```
data_generation/  synthetic customers / accounts / transactions / rule alerts (CSV)
      │  uploaded to UC Volume  aml_bronze.landing
      ▼
[Lakeflow]  Spark Declarative Pipeline  fcc_aml_ingest  (sql/lakeflow/*.sql)
      bronze (Auto Loader streaming tables) → silver (expectations) → gold (alert_features, alert_kpis)
      │
[Unity Catalog]  national_id column mask · PII tags · customers_governed view · grants · lineage
      │
[ML]       RandomForest alert-priority model → MLflow → UC model alert_priority_model@champion
           → gold.alert_scores (score, rank, band, top-3 SHAP reasons per alert)
      │
[Gen AI]   ai_query(Claude Opus 4.8) → gold.alert_sar_drafts (rationale + SAR draft per HIGH alert)
      │
      ▼  gold.case_queue  (score + reasons + SAR draft + masked customer attributes)
[Lakebase] synced table → Postgres aml_serving.case_queue ──► [Databricks App] fcc-case-cockpit
                                                                 │ analyst files SAR / escalates / closes
           Postgres fcc_app.case_dispositions  ◄─────────────────┘  (transactional write)
      │
      ▼  job fcc_dispositions_to_uc → gold.case_dispositions → gold.case_status
[Genie Room]  alert_kpis + case_queue + case_status + customers_governed
              ("How many high-priority alerts are still open?") — also asked from inside the app
```

The loop closes: an analyst's decision in the app (Lakebase) flows back into Unity Catalog, and
Genie answers from it. After one SAR was filed and one case escalated in the app, Genie reports
**120** open high-priority alerts (121 minus the filed SAR; escalated cases stay open) — the same
queue the app shows ([runs/08](runs/08_app.txt), [runs/09](runs/09_genie.txt)).

## 6. Reproduce it

```bash
python3 data_generation/generate_raw_data.py            # synthetic CSVs (seed 42; counts reproduce exactly, txn/alert UUIDs differ per run)
# upload data_generation/raw/<table>.csv to /Volumes/<catalog>/aml_bronze/landing/<table>/
PROFILE=<profile> ./lakebase/setup_lakebase.sh project
databricks bundle deploy && databricks bundle run fcc_end_to_end      # Lakeflow → UC → ML → GenAI → case queue
PROFILE=<profile> ./lakebase/setup_lakebase.sh sync                   # set case_queue_sync_pipeline_id from the output
PROFILE=<profile> WAREHOUSE_ID=<id> ./genie/deploy_space.sh --without-status   # set genie_space_id
databricks bundle deploy && databricks bundle run fcc_cockpit
PROFILE=<profile> ./lakebase/setup_lakebase.sh grant
databricks bundle run fcc_dispositions_to_uc
PROFILE=<profile> WAREHOUSE_ID=<id> SPACE_ID=<id> ./genie/deploy_space.sh      # add case_status to Genie
```

## 7. Decisions & trade-offs

See [`docs/decisions.md`](docs/decisions.md): why ML prioritizes rather than replaces the rules,

## 8. How AI was used

Built with **Claude Code** as a pair-programmer, using the Databricks agent skills (bundles,
Lakeflow pipelines, Lakebase, Apps, Genie) for API-accurate code. The author chose the industry
and customer problem; Claude Code proposed the value model and the trade-offs, which the author
reviewed and adopted, and generated and debugged the code against the live workspace. Examples of AI-assisted debugging during this build, each fixed in code:

- Metastore tag policies rejected the first PII tag values → switched to the governed values.
- A pinned SHAP version broke on the current serverless numpy and silently fell back to impurity
  importances → unpinned SHAP and removed the fallback so a failure stops the job.
- The first SAR prompt passed the synthetic ground-truth typology to the LLM → removed it so drafts
  use only facts an analyst would have; ground truth is used for evaluation only.
